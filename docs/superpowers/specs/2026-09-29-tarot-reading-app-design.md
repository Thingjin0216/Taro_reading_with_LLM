# 밤의 타로 — 설계

2026-09-29

## 왜 만드는가

포트폴리오/데모용 AI 타로 리딩 웹앱. "AI와 인터랙티브 UI를 다룰 줄 안다"를 배포 링크 하나로 보여주는 것이 목적이다. 방문자가 3분 안에 고민 입력부터 후속 대화까지 끝까지 체험할 수 있어야 하고, 화면이 예뻐야 한다.

범위 밖: 결제, 회원가입, 대규모 운영, 리딩 기록 저장.

## 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 스택 | Next.js App Router 풀스택 | 키를 서버에 숨기면서 배포가 한 번, 스트리밍·이미지 최적화가 기본 경로 |
| 스프레드 | 3카드(과거·현재·미래) + 후속 대화 | 구현 부담 대비 데모 임팩트가 가장 좋음 |
| 덱 | 라이더-웨이트 실사 78장, 정/역방향 | 퍼블릭 도메인이라 쓸 수 있고 "타로답다" |
| 카드 선택 | 뒷면 그리드에서 3장 클릭 | 모바일에서 가장 안정적 |
| 해석 화면 | 카드 아래로 이어지는 단일 칼럼 | 모바일과 같은 구조라 반응형이 단순 |
| 톤 | 깊은 밤 + 금색 | 실사 카드 이미지와 가장 잘 붙음 |
| LLM | 서버측 키, 없으면 데모 폴백 | 배포된 데모가 키 없이도 늘 동작 |
| 저장소 | 없음 (서버 무상태) | 데모에 필요 없고 개인정보 부담도 없음 |

## 구조

클라이언트가 78장을 섞어 뒷면 그리드로 보여주고, 사용자가 고른 세 자리를 `{id, reversed, position}`으로 서버에 보낸다. 서버는 **넘어온 카드 id를 덱과 대조해 다시 검증**하고(신뢰하지 않는 입력) 프롬프트를 조립해 텍스트를 스트리밍한다.

후속 대화도 무상태다. 클라이언트가 매 요청에 질문·카드·첫 해석·후속 대화를 함께 보낸다. 첫 해석은 대화 턴이 아니라 고정 맥락으로 따로 받아, 서버가 후속 대화를 최근 12개 메시지로 잘라도 남는다. 사용자 질문은 500자, 후속 질문은 10번으로 제한한다.

해석을 만드는 쪽은 `ReadingProvider` 인터페이스 뒤에 있다. `ANTHROPIC_API_KEY`가 있으면 Anthropic 구현이, 없으면 카드 키워드를 엮는 데모 구현이 응답한다. 응답 헤더 `x-reading-mode`로 어느 쪽인지 알린다.

## 검증 방법

- 단위(vitest): 덱 무결성, 뽑기, 요청 스키마, 프롬프트 조립, 한국어 조사, 스트림 취소·실패, 레이트 리밋
- e2e(playwright): 키를 비운 프로덕션 빌드에서 랜딩→질문→3장 선택→해석→후속 대화. `prefers-reduced-motion`에서도 한 번 더

## 남긴 한계

- 레이트 리밋이 인스턴스 메모리라 서버리스에서 완전하지 않다. 실서비스라면 공유 저장소로 옮긴다.
- 카드 이미지 수집이 위키미디어 레이트 리밋에 걸릴 수 있다. 스크립트가 `Retry-After`를 따르고, 재실행하면 빠진 장만 채운다.

## 변경 — 2026-09-30: EXAONE 연동

API 키 없이 실제 모델을 쓰려고 OpenAI 호환 서버를 붙일 수 있게 했다. 모델 선택 순서는 Claude 키 → `LLM_BASE_URL` → 데모다.

- **모델**: EXAONE 4.0.1 32B(텍스트 전용). 최신 4.5 33B는 비전-언어 모델이고 이 서버의 vLLM 0.15.1이 지원하지 않아, 연구용 `jelly` 환경을 건드리지 않는 쪽을 골랐다. 앱 코드는 OpenAI 호환이라 나중에 모델만 바꾸면 된다.
- **서빙**: `scripts/setup-exaone-env.sh`가 전용 conda 환경 `taro-exaone`(vLLM 0.30.0+cu129)을 만들고, `scripts/serve-exaone.sh`가 그 환경만 쓰도록 격리해 `127.0.0.1:8765`에 띄운다. 처음엔 연구용 `jelly` 환경의 vLLM을 빌려 썼으나 그 환경의 flashinfer 버전 불일치에 우회책을 덧대야 해서 옮겼다. 격리하며 드러난 CUDA 빌드·PATH·libstdc++ 문제와 대응은 README의 "왜 전용 환경인가"에 있다.
- **프롬프트**: 첫 해석과 후속 답변의 시스템 프롬프트를 나눴다. 채점 결과와 이유는 README의 "프롬프트를 이렇게 다듬었습니다"에 있다.
- **한계**: 모델이 GPU 서버에서만 돌아 배포본은 여전히 데모 모드다. 라이선스는 EXAONE AI Model License 1.2 - NC(비상업).

## 변경 — 2026-09-30: 커밋 전 정리

재사용·단순화·효율·근본 수준의 네 관점으로 전체를 검토하고 고쳤다. 동작이 바뀐 것은 다음 셋이다.

- **첫 해석을 고정 맥락으로**: 해석을 assistant 차례로 보내던 때는 7번째 후속 질문부터 기록에서 잘려 나갔고, 모델이 그 다섯 문단을 따라 해 후속 답변에서도 세 장을 다시 풀이했다. 시스템 프롬프트의 맥락으로 옮긴 뒤 EXAONE 후속 답변 8편이 모두 짧은 직답이 되었고, 7번째 질문에도 첫 해석의 카드를 기억한다.
- **실패한 후속 질문 되돌리기**: 답이 한 글자도 오지 않으면 질문을 대화에서 거두고 입력창에 돌려놓는다. 예전엔 깜박이는 빈 말풍선이 남고 질문 횟수만 줄었다.
- **샘플링 기본값은 모델 서버에**: 범용 OpenAI 호환 클라이언트가 EXAONE용 temperature를 들고 있지 않고, 서빙 스크립트가 vLLM에 건다.

그 밖에 두 라우트의 공통 처리를 `parseRequest`로, 카드 풀이 규칙을 `describeDrawn`으로 모았다. 모델 출력 렌더링도 `ModelText` 하나로 맞췄다. 폰트는 쓰는 굵기(400)만 받는다(첫 화면을 막는 CSS가 gzip 119KB에서 36KB로 줄었다). 상수를 zod 스키마에서 떼어 브라우저 번들에서 zod를 뺐다(가장 큰 클라이언트 청크가 145KB에서 69KB로 줄었다).
